# 目录层级与双链关系

三个视图共用真实目录和 Obsidian 内部链接。虚拟根节点使用知识库名称；所有文件夹（包括空文件夹）和 Markdown 文件分别成为节点。附件不成为节点，但随所属文件夹一起移动。

## 层级与链接

- 文件夹是唯一的父级来源，每个笔记直属所在文件夹；根目录中的文件直属虚拟根。
- 文件夹与同名笔记分开显示，例如“项目/”和“项目/项目.md”是两个节点。笔记不会自动转换成文件夹。
- 正文链接、笔记嵌入和属性中的原生内部链接统一形成跳转；入链与出链都可浏览，重复引用只画一条连线。
- 父子线与跳转线常驻显示。不存在普通引用分类、悬停显示策略、显示全部双链开关或外围归属开关。
- 孤立笔记没有连接其他现存 Markdown 笔记的入链和出链。目录、附件、网页链接、自身链接和未创建的目标均不影响判定。统计依据全库关系，不受当前视图筛选、折叠或节点上限影响。

## 操作与历史

目录操作使用 Obsidian 文件管理 API。新增父级会创建文件夹并移入当前文件；新增子项只适用于文件夹；同级操作按来源的实际目录放置目标。普通拖动调整显示布局。移动文件后的链接更新遵循 Obsidian 自身设置。

添加跳转向来源笔记正文追加原生内部链接；任一方向已有连接时不重复添加，也不替换目录关系。连线菜单列出实际引用来源并打开笔记编辑，双向引用可以选择任一来源；没有自动清除正文引用的菜单。

目录操作和新增链接共用串行事务与会话历史，最多 100 项。重名、后代移动、外部替换和编辑冲突都会停止操作；失败时补偿已完成步骤，补偿失败明确报告路径。撤销新建文件不会删除用户后来编辑的内容。

## 版本 4 迁移

工作区就绪后先逐篇迁移，再启动索引和关系写入。旧 brain-jumps 中有效 wiki 链接追加到正文，保留别名、标题和块定位，尚未创建的目标同样保留。成功后删除 brain-jumps 与 brain-parents；旧父级不转成目录或跳转。

迁移按文件原子执行、可重复运行。损坏 YAML、无效条目或并发修改使该文件原文保留并报告路径；其他文件继续迁移，修复后重载可重试。失败文件的旧属性不参与运行时关系。

插件数据升级为版本 4，清除局部关系布局和废弃设置，保留有效的导航、主题外观及世界视图配置。旧根节点命令 ID 保留，行为固定为返回知识库根节点。
